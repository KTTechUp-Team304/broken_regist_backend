수강신청 기반 취약점 학습 서비스 - 1차 MVP API 상세 문서
=========================================================

목적
----
이 문서는 1차 MVP에서 웹이 자연스럽게 노출할 API와 취약점 표면을 정리한다.
웹은 일부러 만든 실습용 API보다 실제 수강신청/관리자 기능처럼 보이는 허술한 구현을 우선한다.
MCP는 이 허술한 기능 표면을 분석하여 OWASP Top 10:2025 취약점을 발견하는 흐름으로 맞춘다.

수정·설정 변경과 삭제 요청은 DELETE/PATCH 대신 POST로 통일한다.

DB 스키마 기준
--------------
요청/응답 데이터는 현재 엔티티에 존재하는 필드를 기준으로 작성한다.

- `users`: `id`, `username`, `passwordHash`, `role`, `createdAt`
- `professors`: `id`, `userId`, `displayName`, `departmentName`
- `courses`: `id`, `code`, `name`, `description`, `professorId`, `category`, `maxCapacity`, `currentCount`, `isVisible`, `createdAt`
- `enrollments`: `id`, `userId`, `courseId`, `status`, `enrolledAt`, `droppedAt`
- `files`: `id`, `courseId`, `uploaderId`, `originalName`, `storedPath`, `mimeType`, `fileSize`, `isPublic`, `uploadedAt`
- `refresh_tokens`: `id`, `userId`, `tokenHash`, `issuedAt`, `expiresAt`, `revokedAt`, `deviceInfo`
- `audit_logs`: `id`, `userId`, `action`, `resourceType`, `resourceId`, `ipAddress`, `requestMethod`, `requestPath`, `responseStatus`, `createdAt`
- `error_logs`: `id`, `errorType`, `message`, `stackTrace`, `requestPath`, `requestMethod`, `requestBody`, `userId`, `createdAt`
- `debug_configs`: `id`, `configKey`, `configValue`, `isSensitive`, `description`, `updatedAt`, `updatedBy`
- `cors_policies`(선택/향후): 1차 MVP에서는 관리 API를 두지 않는다. DB에는 행을 둘 수 있지만 노출 표면은 다른 misconfiguration 경로로 다룬다.

비영속 응답 예외
----------------
`accessToken`, `refreshToken`, `dependencies`, `buildInfo`처럼 DB 테이블에 저장되지 않는 값은 API 동작상 필요한 경우에만 "비영속 응답"으로 표시한다.

OWASP Top 10:2025 최종 점검
---------------------------
- A01 Broken Access Control: 사용자/수강신청/파일/admin API의 IDOR와 권한 우회로 충족한다.
- A02 Security Misconfiguration: debug config, error log, 운영 설정 노출, 내부 경로 노출로 충족한다.
- A03 Software Supply Chain Failures: dependency/build 정보 노출로 충족한다.
- A04 Cryptographic Failures: JWT/refresh token 구성, secret 노출, 만료되지 않는 파일 링크로 충족한다.
- A05 Injection: 로그인/회원가입의 계정 조회, 강의 검색/필터, audit log 검색, raw query 테스트로 충족한다.
- A06 Insecure Design: 정원 초과, 중복 신청, 신청 기간 미검증 등 서버 검증 부재, 숨김 강의 공개 조작으로 충족한다.
- A07 Authentication Failures: 비밀번호 복잡도/길이 정책 없음, 로그인 제한 없음, token 폐기 실패로 충족한다.
- A08 Software or Data Integrity Failures: 목데이터 파일 삭제 후 복구성 확인, debug config 변조로 충족한다.
- A09 Security Logging and Alerting Failures: 로그 조회/삭제, 보안 이벤트 누락으로 충족한다.
- A10 Mishandling of Exceptional Conditions: 별도 crash API 없이 기존 기능 API의 5xx, stack trace, 내부 경로, parser error 노출로 충족한다.

[API]
POST /api/auth/register

[기능]
- 회원가입
- 기본 role은 `student`로 생성한다.

[요청데이터]
- 헤더
  - `Content-Type: application/json`
- 바디
  - `id`: `users.id`, 정상 구현에서는 클라이언트 입력을 무시해야 하지만 취약 구성에서는 중복 확인 raw query에 섞일 수 있음
  - `username`: `users.username`
  - `passwordHash`: `users.passwordHash` 생성에 사용되는 원문 비밀번호 입력값
  - `role`: `users.role`, 취약 구성에서는 사용자가 `admin` 또는 `professor`를 직접 전달할 수 있음
- 공격이 들어오는 방법
  - `role=admin` 전달로 권한 상승 시도
  - `username=admin' OR '1'='1' --` 형태로 중복 확인 SQL 조작
  - `id=1 AND LEFT(password_hash,1)='a'` 형태의 조건을 넣어 에러/응답 차이 기반 blind SQL Injection 유도
  - `username` 50자 초과 입력 시, 서버가 사전 검증 없이 DB까지 전달하여 컬럼 길이 에러/stack trace를 노출하는지 확인
  - 비밀번호 입력값 또는 취약하게 생성된 `passwordHash`가 255자를 넘도록 하여 `users.passwordHash` 길이 제한 에러 유도
  - `id`에 bigint 범위를 초과하는 매우 큰 숫자 또는 문자열을 넣어 casting/DB 에러 유도
  - 비정상 JSON으로 예외 유도

[응답데이터]
- 정상 응답
  - `id`, `username`, `role`, `createdAt`
- 취약점 노출 응답
  - 비밀번호 복잡도/길이와 무관하게 계정 생성 성공
  - 사용자가 전달한 `role=admin`이 그대로 반영된 응답
  - SQLi payload에 따라 중복 계정 여부, DB 에러, `LEFT` 함수 결과 차이가 응답으로 드러남
  - 길이 초과 입력 시 컬럼명, 제한 길이, DB 에러 메시지, `stackTrace` 노출
  - 중복 가입/비정상 입력 시 `message`, `stackTrace`, `requestBody`가 포함된 에러 응답

[API]
POST /api/auth/login

[기능]
- 로그인
- JWT access token 발급
- refresh token 발급 및 `refresh_tokens` 저장

[요청데이터]
- 헤더
  - `Content-Type: application/json`
- 바디
  - `username`: `users.username`
  - `passwordHash`: `users.passwordHash` 비교에 사용되는 원문 비밀번호 입력값
- 공격이 들어오는 방법
  - 동일 계정에 대한 반복 로그인 시도
  - `username=admin' --` 형태로 비밀번호 조건 우회
  - `username=admin' OR '1'='1' --` 형태로 첫 번째 사용자 인증 유도
  - `username=admin' AND LEFT(password_hash,1)='a' --` 형태의 blind SQL Injection으로 `passwordHash` 일부 추론
  - `username` 50자 초과 또는 비밀번호 255자 초과 수준의 긴 문자열로 DB/비교 로직 에러 유도
  - malformed JSON body 전송
  - `X-Test-Delay: true` 헤더로 timeout 처리 확인

[응답데이터]
- 정상 응답
  - 사용자: `id`, `username`, `role`, `createdAt`
  - 비영속 응답: `accessToken`, `refreshToken`
- 취약점 노출 응답
  - 반복 로그인에도 차단/지연/429 응답이 동작하지 않음
  - SQLi payload로 비밀번호 비교를 우회해 로그인 성공
  - `LEFT(password_hash,1)` 조건 결과에 따라 401/500/응답 시간 차이가 발생
  - 길이 초과 입력 시 컬럼명, 제한 길이, DB 에러 메시지, `stackTrace` 노출
  - refresh token이 장기간 유효하거나 재사용 가능
  - 에러 응답에 `passwordHash` 비교 실패 사유, `stackTrace`, `requestBody` 노출

[연결 UI]
- 로그인 / 회원가입 페이지

[노출 취약점]
- A07: 로그인 시도 제한 없음
- A04: JWT/refresh token 취약 구성
- A05: 로그인 SQL Injection
- A10: malformed input 또는 timeout 처리 실패

[API]
GET /api/courses

[기능]
- 강의 목록 조회
- 검색 및 카테고리 필터링

[요청데이터]
- 헤더
  - `Authorization: Bearer <accessToken>`
- 바디
  - 없음
- Query
  - `keyword`: `courses.name`, `courses.code`, `courses.description` 검색에 사용
  - `category`: `courses.category`
  - `isVisible`: `courses.isVisible`
- 공격이 들어오는 방법
  - `keyword=' OR '1'='1`
  - `category=' OR is_visible=false --`
  - `isVisible=false` 직접 전달로 숨김 강의 조회
  - `q`, `keyword`에 `@@`, `1/0`, `<script>` 입력으로 예외 유도

[응답데이터]
- 정상 응답
  - 목록 항목: `id`, `code`, `name`, `description`, `professorId`, `category`, `maxCapacity`, `currentCount`, `isVisible`, `createdAt`
- 취약점 노출 응답
  - `isVisible=false` 강의까지 반환
  - Injection payload로 전체 강의 반환
  - 에러 응답에 raw SQL, `Error:`, `stackTrace` 노출

[연결 UI]
- 강의 목록 페이지

[노출 취약점]
- A05: SQL Injection
- A01: 숨김 강의 접근 제어 실패
- A10: 검색 조건 예외 처리 실패

[API]
POST /api/enrollments

[기능]
- 수강 신청

[요청데이터]
- 헤더
  - `Authorization: Bearer <accessToken>`
  - `Content-Type: application/json`
- 바디
  - `userId`: `enrollments.userId`
  - `courseId`: `enrollments.courseId`
  - `status`: `enrollments.status`, 기본값 `enrolled`
- 공격이 들어오는 방법
  - `userId`를 다른 사용자의 `users.id`로 변경
  - 프론트에서 신청 버튼이 비활성화된 정원 마감 강의의 `courseId`를 직접 요청하여 서버 측 정원 검증 우회
  - 정원 마감 강의에 동시 요청 전송
  - 같은 `courseId`를 반복 전송
  - `status=dropped` 또는 잘못된 enum 값 전송
  - `X-Test-Delay: true` 헤더로 timeout 처리 확인

[응답데이터]
- 정상 응답
  - `id`, `userId`, `courseId`, `status`, `enrolledAt`, `droppedAt`
  - 관련 강의 상태: `id`, `maxCapacity`, `currentCount`
- 취약점 노출 응답
  - 다른 `userId`로 수강신청 성공
  - `currentCount >= maxCapacity`인 강의에도 수강신청 성공
  - `currentCount > maxCapacity` 상태의 강의 반환
  - 중복 신청 DB constraint 에러, raw error, `stackTrace` 노출
  - timeout 상황에서 500 또는 응답 지연

[연결 UI]
- 강의 상세 페이지
- A10 예외 처리 취약점 탐지 흐름

[노출 취약점]
- A06: 프론트 상태에만 의존한 서버 측 정원 검증 부재
- A06: race condition으로 정원 초과
- A06: 중복 신청/신청 정책 우회
- A01: 다른 user 요청 가능
- A10: 동시성/DB 예외 처리 실패

[기능]

[요청데이터]

  - 없음

[API]
GET /api/debug/secrets

[기능]
- secret 조회
- 실제 서비스에는 없어야 하지만, 운영 중 잘못 노출된 관리자 진단 기능처럼 둔다.

[요청데이터]
- 헤더
  - `Authorization: Bearer <accessToken>`
- 바디
  - 없음
- 공격이 들어오는 방법
  - 일반 사용자 token으로 호출
  - `debug_configs.isSensitive=true` 값 조회

[응답데이터]
- 정상 응답
  - `id`, `configKey`, `configValue`, `isSensitive`, `description`, `updatedAt`, `updatedBy`
- 취약점 노출 응답
  - JWT secret, DB password, API key에 해당하는 `configValue` 노출

[연결 UI]
- 관리자 - 시스템 / 보안 설정 페이지

[노출 취약점]
- A04: secret 노출
- A02: debug endpoint 노출
- A01: 관리자 진단 API 접근 우회


---------------
[API]
POST /api/debug/query-test

[기능]
- raw query 테스트
- 운영 중 잘못 남은 관리자 진단 API로 둔다.

[요청데이터]
- 헤더
  - `Authorization: Bearer <accessToken>`
  - `Content-Type: application/json`
- 바디
  - `requestPath`: `audit_logs.requestPath` 또는 `error_logs.requestPath` 형태의 테스트 대상 경로
  - `requestMethod`: `audit_logs.requestMethod` 또는 `error_logs.requestMethod`
  - `requestBody`: `error_logs.requestBody`
- 공격이 들어오는 방법
  - raw SQL 조각 전달
  - 일반 사용자 token으로 호출
  - malformed JSON body 전송

[응답데이터]
- 정상 응답
  - `requestPath`, `requestMethod`, `requestBody`
- 취약점 노출 응답
  - raw query 실행 결과 또는 DB 에러 반환
  - `stackTrace`, SQL 문장, `requestBody` 노출

[연결 UI]
- 관리자 - 시스템 / 보안 설정 페이지

[노출 취약점]
- A05: Injection
- A02: debug endpoint 노출
- A10: raw query 예외 처리 실패
